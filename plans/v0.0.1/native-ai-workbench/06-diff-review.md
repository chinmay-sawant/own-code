# Agent change review

**Goal:** Let the user review own-code agent proposals and accept, reject, or revert edits without losing existing work.

**Implementation note (2026-11-28):** The worktree manager creates a random detached Git worktree under the private user-config directory. It maps selected subdirectories, starts at committed `HEAD`, refuses checkout filters and tracked symlinks, disables inherited Git configuration, hooks, and fsmonitor during checkout, and validates containment and Git registration before non-forcing cleanup. A reopen helper revalidates the original repository and saved base commit after restart. `opencode_proposal_snapshot.go` takes a bounded read-only snapshot of created, modified, deleted, and renamed text files relative to that commit; it rejects binary, symlink, traversal, control-character, and oversized changes. The local Console agent stages proposal bytes separately from the checkout, routes edit proposals to the existing diff views, and applies changes only after review. A worktree is not an OS sandbox and does not restrict an approved shell command's filesystem or network access.

**Review implementation (2026-11-28):** `internal/agentreview` owns hunk diff/apply/revert, whole-file delete/rename units, baseline capture, path mapping, and state transitions. `internal/app/opencode_hunks.go` wires actions to disk or the open buffer through `replaceEditRanges`, preserving undo and dirty-state behavior. `opencode_diffview.go` shows session/file/hunk state and Accept/Reject/Revert controls in unified and split views. Baselines are captured at turn start and proposals touching pre-existing user changes carry an attribution note. Binary and oversized changes remain explicitly unavailable for hunk review.

Proposal bytes are staged under the private `agent-workbench/proposals` directory; per-session proposal metadata and hunk states are stored under `agent-workbench/proposal-state`. Session-load workers validate bounded files and hashes, reconstruct reviews, and pass prepared state to the UI. The UI thread only installs that state. Changed baselines, symlinks, out-of-root paths, dirty buffers, staged edits, and rename collisions are refused at acceptance. Focused persistence, snapshot, hunk, and app tests pass. Still open: live model use of `delete_file` and `move_file`, live restart/UI acceptance, and the full repository build/test/race/vet/lint gate.

## Phase 1: Isolate proposed edits

- [x] Choose an isolation mechanism before connecting agent writes to the main workspace: a private worktree or another patch-backed staging area.
- [x] Keep agent writes away from the user's checked-out files until the review contract is proven.
- [x] Capture the pre-agent worktree, index, and open dirty buffers so the review can distinguish user changes from agent changes. (`CaptureBaseline` at turn start in `executeOpenCodeTurn`; `TestAgentProposalClassificationAndBaselineAttribution`. Attribution is surfaced as a note only.)
- [x] Map every agent-produced path to a file under the selected workspace. Reject traversal, symlink escape, and out-of-root changes. (`agentreview.MapPath`, `TestReviewMapPathRejectsEscapes`; used by `recordAgentReview`.)
- [x] Handle create, delete, rename, binary, and oversized files explicitly. (Create/binary/oversized as before. Delete and rename: `delete_file` and `move_file` tools (policy ask) stage a `Proposal{Deleted}` / `Proposal{RenamedFrom}` in the proposal root only; `ApplyProposal` rechecks baseline hash, symlinks, containment, and rename-destination collisions; `agentreview.PutWhole` makes each a single accept/reject unit with no hunks; the app applies it with the same dirty-buffer and Git-state refusals and closes the open tab on accept. Tests: `TestDeleteProposalStagesWithoutTouchingCheckoutThenApplies`, `TestDeleteBaselineChangedAndMissingRefused`, `TestDeleteSymlinkAndOutsideRefused`, `TestMoveProposalAppliesOnlyWhenBaselineMatches`, `TestMoveCollisionRefused`, `TestWholeFileUnitHasNoHunksAndResolvesOnce`, `TestOpenCodeAgentDeleteAndRenameProposals`.)
- [x] Include rename records in the read-only worktree snapshot. Parse NUL-delimited rename statuses, validate both paths and endpoints, and generate a two-path rename diff. Evidence: `TestParseOpenCodeProposalNameStatusRename`, `TestParseOpenCodeProposalNameStatusRejectsUnsafeRename`, `TestOpenCodeProposalSnapshotIncludesRename`, `TestOpenCodeProposalSnapshotRejectsSymlinkRenameTarget`.

**Gate:** A fake agent edit cannot alter the main workspace before review. Pre-existing staged, unstaged, and dirty-buffer changes remain attributable to the user.
